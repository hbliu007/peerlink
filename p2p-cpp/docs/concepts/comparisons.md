# 方案对比

PeerLink 与其他 P2P/NAT 穿透方案的详细对比。

---

## PeerLink vs Tailscale

| 维度 | PeerLink | Tailscale |
|------|----------|-----------|
| **部署模式** | 完全自托管 | SaaS（托管版）+ 自托管（Headscale） |
| **第三方依赖** | 无 | DERP 服务器（Google Cloud） |
| **控制平面** | 自己的 Signaling 服务器 | Tailscale Coordination Server |
| **NAT 穿透** | UDP/TCP 打洞 + Relay | DERP + DERP Map |
| **身份系统** | DID (Decentralized Identity) | OAuth/OpenID Connect |
| **加密方式** | TLS 1.3 + Ed25519 | Noise Protocol |
| **协议实现** | C++20 | Go |
| **开源程度** | 完全开源 | 客户端开源，服务端闭源 |
| **成本** | 服务器成本 | 免费 tier + 付费 tier |
| **适用场景** | 企业内网、私有化部署 | 个人/小团队快速上手 |

### 总结

- **选择 PeerLink**: 如果你需要完全自主可控、不想依赖任何第三方服务
- **选择 Tailscale**: 如果你追求最快上手速度，不依赖第三方不是硬性要求

---

## PeerLink vs FRP

| 维度 | PeerLink | FRP |
|------|----------|-----|
| **连接方式** | P2P 直连优先，降级到中继 | 始终走中继 |
| **NAT 穿透** | 支持 UDP/TCP Hole Punching | 不支持 |
| **延迟** | 直连 < 10ms，中继 < 50ms | 中继 < 50ms |
| **带宽** | 直连无限制，中继受限于服务器 | 受限于服务器 |
| **服务器负载** | 仅直连失败时使用 | 始终占用 |
| **配置复杂度** | 自动 NAT 检测和打洞 | 需要配置转发规则 |
| **适用场景** | 高带宽需求、实时通信 | 简单端口映射 |

### 总结

- **选择 PeerLink**: 如果需要高带宽、低延迟的实时通信（如远程桌面、文件传输）
- **选择 FRP**: 如果只是简单的端口映射需求

---

## PeerLink vs ZeroTier

| 维度 | PeerLink | ZeroTier |
|------|----------|----------|
| **网络层** | 应用层 P2P | 虚拟网卡 (Layer 2) |
| **NAT 穿透** | UDP/TCP 打洞 + Relay | UDP 打洞 + Root Server |
| **控制平面** | 自己的 Signaling 服务器 | ZeroTier 根服务器或自托管 |
| **身份系统** | DID | 40-bit Node ID |
| **加密方式** | TLS 1.3 + Ed25519 | AES-256-GCM + ECDH |
| **协议实现** | C++20 | C++ |
| **开源程度** | 完全开源 | BSL许可证（商业使用需付费） |
| **部署难度** | 简单（Docker 一键部署） | 中等（需要配置控制器） |
| **网络隔离** | 应用层隔离 | 完整的虚拟网络隔离 |

### 总结

- **选择 PeerLink**: 如果需要应用层的 P2P 通信，不需要完整的虚拟网络
- **选择 ZeroTier**: 如果需要创建完整的虚拟网络（Layer 2），像局域网一样使用

## NAT 穿透能力对比

| NAT 类型 | PeerLink | Tailscale | FRP | ZeroTier |
|----------|----------|-----------|-----|----------|
| **Full Cone** | ✅ UDP | ✅ DERP | ❌ | ✅ UDP |
| **Restricted Cone** | ✅ UDP | ✅ DERP | ❌ | ✅ UDP |
| **Port-Restricted Cone** | ✅ UDP | ✅ DERP | ❌ | ⚠️ 部分 |
| **Symmetric** | ⚠️ TCP/Relay | ✅ DERP | ❌ | ⚠️ TCP/Relay |
| **企业防火墙** | ✅ TCP 443 Relay | ✅ DERP | ✅ 代理 | ✅ TCP/Relay |

## 选择建议

### 场景 1: 企业内网远程访问

**推荐**: PeerLink

- 穿透企业防火墙（TCP 443 Relay）
- 完全自主可控，不依赖第三方
- 支持大规模部署

### 场景 2: 个人开发者远程桌面

**推荐**: Tailscale

- 最快上手速度
- 客户端支持丰富（Windows/macOS/Linux/iOS/Android）
- 免费 tier 足够个人使用

### 场景 3: 简单端口映射

**推荐**: FRP

- 配置简单
- 资源占用小
- 适合单一服务映射

### 场景 4: 虚拟局域网

**推荐**: ZeroTier

- 完整的 Layer 2 虚拟网络
- 像局域网一样使用
- 支持网络隔离

### 场景 5: 高带宽实时通信

**推荐**: PeerLink

- P2P 直连优先
- 无带宽限制
- 低延迟
